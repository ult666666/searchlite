# Compare two local retrieval configurations

Intent: developers can evaluate their own saved notes today, but before/after comparison uses only the fixed glossary workbench. Add a maintained source-consumer command that runs both actual saved indexes against the same local labels, exposes per-query rankings/deltas and refuses a regression hidden by averages. User delegated AI-tool engineering and routine choices; this is the implementer's scoped choice, not a claim of user-specified API.

Approaches: manually diff two evaluation reports (no automated comparability/gate); add browser private-file import (larger UI/data-lifecycle surface); extend the existing local CLI (chosen: reuse its real safe reader, validation, evaluator and terminal-safe serializer). No new library API/dependency/schema version for existing commands.

Contract: node examples/search-docs.js compare BASELINE CANDIDATE JUDGMENTS, exactly four arguments afterscript; existing index/search/evaluate syntax/output unchanged. Both snapshots pass existing bounded title/body reader. They must contain identical document IDs and stored title/body text, irrespective of document order; configuration/posting differences are allowed. Compare canonical sorted [id,title,body] triples exactly and record their SHA256. This establishes comparability of supplied stored text, not snapshot/source authenticity or current filesystem state. Changed/missing/added content is refused INCOMPARABLE_COLLECTION before a report. No original folders are read.

Read each snapshot once through existing owned-byte loader and judgments once through existing256KiB reader. Evaluate both using one factored existing report function; no report-input trust, no subprocesses/network/providers/writes. Existing16MiB/snapshot,128docs,1MiBbody corpus,32queries/128labels perquery remain. Preserve malformed/linked/nonregular/oversize/UTF8/query diagnostics and empty stdout on any error.

New schema searchlite.local-comparison/1 contains exact used input hashes, collection hash/counts, baseline/candidate configuration+status+failed minima, shared cutoffs/criteria, each query's ID/text/labels/minimum and actual sides' ranking/metrics/missing relevant/passed minimum, candidate-minus-baseline deltas, regressed IDs, failed-minimum IDs and union failed IDs in manifest order. No source bodies, absolutepaths, clocks/randomness. JSON terminal-control escaping shared.

Exit0 only if every candidate query meets its existing unrounded minimumNdcgAt10 AND candidate unrounded nDCG@10 >= baseline. Any drop fails even if average improves or a minimum still passes. No tolerance/statistical claim; differences in other metrics remain visible but do not gate. Valid unmet comparison emits full report/exit3; usage2; malformed/unsafe/incomparable1/empty stdout. Baseline minimum failure is reported but does not independently veto a passing improved candidate. Scores are scoped to each configuration, never subtracted or treated as comparable.

Verification: real process tests through built exports; literal hand-derived reorder/delta, minimum-met regression with offsetting improved query, unchanged candidate, improved baseline-failure, every used-byte hash and deterministic rerun after source deletion, identical collection with reordered records, changed/add/remove refusal, invalid/oversize/UTF8/linked/nonregular files on either side and judgments, malformed queries/manifest, usage, no partial output or input writes, control characters/prototype names. Cross-revision legacy evaluate byte parity. Full existing check/native/filtering/browser/eval green, one independent exact-head review and hosted Node20/22/24 green before shipping.

Non-goals: browser imports, corpus-edit comparison, automatic criteria tuning, universal relevance/speed/model claims, vector/ANN changes, installed executable, snapshot authenticity or organizational authorization. Limits must be explicit in docs.
