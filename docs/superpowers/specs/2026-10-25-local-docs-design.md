# Search a bounded local document collection through the public package

Provide a runnable ESM Node consumer, following `scripts/check-dist.js`: `examples/search-docs.js` imports only built `searchlite` exports plus Node standard libraries. `index DIRECTORY SNAPSHOT` creates a new raw `SearchIndex.toJSON()` file; `search SNAPSHOT QUERY` reloads it through `SearchIndex.fromJSON()` and prints at most five results with a plain snippet, score and public `formatExplanation()` breakdown. No runtime dependency, embeddings, browser surface, provider or network retrieval is added.

Use one document per nonempty UTF-8 `.md`/`.txt` file (case-insensitive extensions), with the full literal file as body, filename without extension as title (boost 3), and a stable root-relative forward-slash path as ID. Walk in code-unit-sorted order. Code and Markdown remain literal searchable text; search uses the saved snapshot, never rereads original documents, and does not automatically refresh changes.

Bound each eligible file to 128 KiB, all eligible bytes to 1 MiB, eligible files to 128, visited directory entries to 4,096, nesting to 16 and a snapshot to 16 MiB. Skip hidden entries, symlinks and these dependency/generated directories: node_modules, bower_components, vendor, dist, build, coverage, out, output, target, generated, __pycache__. Refuse a selected root within those excluded paths, linked roots/snapshots, nonregular or multiply-linked input files, invalid UTF-8, NUL text, inaccessible included files and incompatible snapshots. A failed source scan writes no snapshot.

The caller selects a new snapshot path whose parent exists; existing outputs are never overwritten. Snapshot reload checks bounded document text and the fixed title/body field layout before using the public loader. Snapshots contain document text and are ordinary local data, without authenticity or freshness guarantees. This is an inspectable example for small folders the caller controls, not production filesystem search or a defense against a hostile concurrent filesystem owner.

Output is plain terminal text: collapse snippet whitespace, cap snippet length, and escape control/bidirectional formatting characters in paths, source text, queries, explanations and diagnostics. Exit 0 on successful index/search (including no matches), 1 on input/read/query/snapshot failure, 2 on usage errors. Build the package first; document both commands and every limit/skip rule.

Alternatives: a TypeScript consumer would need a runtime runner and new build/typecheck coupling before dist declarations exist; the established ESM consumer convention runs with Node alone. Reindexing on every query would not demonstrate persisted snapshots; explicit index/search commands make that boundary visible and testable. Parent reviews the exact scoped PR head; no merge.
