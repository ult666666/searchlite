# Check retrieval over a saved local document collection

The shipped local-folder consumer can build/search a bounded snapshot through the installed package's public exports, while the new browser workbench deliberately uses a fixed authored collection. A useful next capability is evaluating a caller's labelled questions against their saved local snapshot, with explicit per-query acceptance criteria. Extend the existing ESM consumer with `node examples/search-docs.js evaluate SNAPSHOT JUDGMENTS`. Keep index/search behavior and all library algorithms unchanged; no private browser upload or external/provider call.

Use the existing safe bounded reader and snapshot validator, returning the same bytes used for reconstruction so SHA-256 identifies the actual read inputs rather than a later reread. Snapshot bounds remain16MiB/128 documents and existing title/body/text limits. Judgment files are at most256KiB, regular/unlinked/read-only valid UTF-8 JSON. Report hashes establish exact input identity, not authenticity or freshness.

Judgment manifest: exact top-level keys `schema` and `queries`, schema `searchlite.local-judgments/1`;1–32 query records with exact keys `id`, `text`, `relevance`, `minimumNdcgAt10`. ID is a unique1–64 character ASCII identifier starting with an alphanumeric and then alphanumeric/dot/underscore/hyphen. Text is nonempty, at most1000 UTF-16 units, with no NUL. Each relevance array has1–128 exact `{documentId,grade}` records; IDs must exist in the loaded index, be unique within that query, and grades must be integers0–3 with at least one positive judgment. Threshold is a finite number in[0,1], required for every query. Refuse unknown fields, duplicate query/document IDs, unknown document references, malformed text/grades/thresholds and invalid query syntax. Ordinary JSON parser semantics apply to object syntax; no duplicate-object-key rejection or source authentication is claimed. Validate all records before retrieval/output. Never interpret document IDs as filesystem paths.

Search each literal query through `index.search(text,{limit:100})`, then compose public `evaluate` at5 and10. Report P@5/R@10/full-ranking MRR/MAP/nDCG@10 without changing denominators or formulas. Each query passes if its unrounded nDCG@10 >= its declared threshold; all queries must pass. The root report schema is `searchlite.local-evaluation/1`, with status pass/fail, input SHA-256/document/query counts, actual saved-index options, collection-independent cutoff/depth definitions, all per-query thresholds/metrics/rankings (IDs,score,grade), missing relevant top10 IDs, and failed query IDs. No timestamps/random values or source document bodies. Query text and relative IDs can be private, so reports stay local unless the caller shares them. JSON string content escapes terminal control/bidirectional/separator characters while retaining valid parseable JSON and original string semantics.

Exit0 for passing report,3 for a valid report missing any criterion,1 for file/manifest/query/snapshot failures,2 for usage. Valid failed criteria still emit complete JSON stdout; malformed input emits no partial report. Existing index/search exit meanings remain. Evaluation writes no input/output files and never rereads original document folders. A controlled fictional three-note example plus manifest demonstrates both passing and deliberately unmet criteria. Thresholds/labels are caller decisions, not statistical significance, production relevance or execution approval.
