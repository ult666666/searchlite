# Measure the existing search engine at two bounded sizes

The README explicitly lists a missing `npm run bench` with documented method/machine/Node version, and the user requested portfolio engineering at a better scale. Complete that source-backed roadmap item with an honest reproducible microbenchmark, not a speed claim or another ranking implementation. Use the built public package in fresh pure-Node worker processes; no dependency/core/formula/browser change.

Default profile is fixed before seeing results:1000 and10000 documents,3 fresh trials per size,2 warmup cycles then4 measured cycles. Smoke profile:60 and120 documents,1 trial each,1 warmup/1 measured cycle. Generate documents by round-robin copying the existing60 glossary entries with unique ordinal-prefixed IDs; copy tags and preserve field text. This intentionally repeats vocabulary and is not a representative production corpus. Use the existing default title3/tags2/body1 field options, default stored fields and top10 results. The26 uniform queries are the existing22 judged question texts plus literal phrase, prefix, Boolean and fuzzy examples. Every call passes query text through the full public search path; no pre-parsed query/cache substitution. Generate/serialize payload before measured work.

Each fresh worker receives the parent's fixed generated workload, times constructor+addAll as buildMs, records process.memoryUsage before/after index construction (whole-process snapshots, not isolated index size or peak), performs complete warmup cycles, then records every search-only latency via performance.now alongside query ID/result count. Each worker returns its actual PID, document count, workload SHA-256 and raw samples. A checksum consumes result counts. Parent uses process.execPath and a pure Node JS worker with no grandchildren; spawnSync has a30-second SIGKILL deadline and2MiB output bound. A failed worker produces no partial root report. No file/network/service access beyond installed code/stdin/stdout.

The benchmark root schema is searchlite.microbenchmark/1, with profile parameters, actual UTC timestamp, machine platform/release/architecture/CPU model/logical-core count/totalRAM, Node/V8 versions, original fixture digest, query text/type mix, independent trials and per-size summaries. Never record username, hostname, environment variables or filesystem paths. Per-size latency min/mean/p50/p95/max pools that size's measured samples across trials; percentile is explicitly nearest-rank ceil(p*N)-1. Build median uses the3 trial values. Preserve raw samples and memory snapshots; no latency threshold, CI speed gate, throughput/service SLA or competing-library comparison. Report notes disclose repeated vocabulary, uniform synthetic mix, finite warmup, runtime/GC/desktop noise, non-independent pooled samples and process-level memory semantics.

CLI `npm run --silent bench -- [--smoke]`; standalone --help. Unknown/duplicate/mixed options exit2 with bounded usage/no argument echo; worker/calculation failure exits1, success JSON only.
